# 파이프라인 기술 문서

최초 작성일: 2026-10-21

## 1. 전체 파이프라인 흐름

```text
1. XML 데이터 수집
   ↓
2. XML 파싱 및 필요한 필드 추출
   ↓
3. 데이터 정제 및 정합성 검증
   ↓
4. 스키마 정의 및 DataFrame 변환
   ↓
5. CSV 파일 저장
   ↓
6. CSV 데이터를 활용한 Plotly 시각화
   ↓
7. GitHub Pages 배포
```

## 2. 추가 데이터 수집 파이프라인
### 데이터 수집 방법 결정
1. 전체 추출: 데이터가 크지 않아 전체 추출이 기술적으로 가능하지만, 과거 데이터가 변경될 가능성이 거의 없어서 적합하지 않음
2. 증분 추출: 과거 데이터가 변경될 여지가 적고, 매일 column 한개만 추가되기 때문에 가장 적합함
    - 추가 정합성 검증이 필요할 경우, 최근 N개월동안의 데이터를 정기적으로 가져와 기존의 CSV와 비교할 수 있음
3. CDC: 중복 데이터, UPDATE나 DELETE 등 기존 데이터의 변경이 일어나지 않기 때문에 CDC를 적용할 이유가 부족함

### 증분 데이터 추출 파이프라인 흐름
```text
1. 추가 수집이 필요한 XML 데이터 조회
   ↓
2. XML 파싱 및 필요한 필드 추출
   ↓
3. 데이터 정제 및 정합성 검증
   ↓
4. 기존 CSV 데이터와 신규 데이터 결합
   ↓
5. 중복 제거 및 데이터 정합성 재검증
   ↓
6. 검증된 데이터를 CSV 파일에 저장
   ↓
7. 최신 CSV 데이터를 활용한 Plotly 시각화
   ↓
8. GitHub Pages 자동 배포
```

## 3. 주요 처리 사항

- **데이터 정제:** `None`, 결측치, 숫자형 변환 등 처리
- **데이터 정합성 검증:** 필수 필드, 날짜 형식, 금리 값 및 중복 여부 확인
- **증분 수집:** 기존 데이터는 유지하면서 신규 데이터를 추가하고, 중복 데이터가 발생하지 않도록 처리
- **시각화 및 배포:** 최신 CSV 데이터를 기준으로 시각화 결과를 생성하고 GitHub Pages에 배포

## 7. 데이터 변환 규칙
- 날짜: mm/dd/YYYY => YYYY-mm-dd
  - 금리: 소수점 하위 자리까지 신경쓸 정도로 정확도가 필요로 하지 않다. => 단순 Python 실수와 RDBMS FLOAT 타입
  - 결측치 처리: Python-None, RDBMS-NULL

## 8. 데이터 품질 검증	
- 중복 날짜
    - AI 권장 모범 사례
    1. 신규 데이터 내부에서 중복 날짜 검사
    2. 기존 CSV와 신규 데이터 결합
    3. date 기준으로 중복 검사
    4. 동일 날짜가 있으면 신규 데이터로 갱신
    5.최종 데이터에 중복 날짜가 없는지 재검증
- 필수 필드 누락
    - date: 재수집 시도 후에도 없으면 해당 레코드 건너뜀
    - 금리 필드: 해당 값만 NULL 처리
- 권장 재시도 정책
    - AI 권장 모범 사례
    - 네트워크 오류: 최대 3회 시도
    - XML 파싱 실패: 재시도 후에도 실패하면 해당 실행을 실패 처리
    - 특정 날짜의 금리값 누락: 정상 결측인지 확인후 NULL 처리
- 금리 값 검증
    - AI 권장 모범 사례
    - 숫자 형 반환 여부: 숫자형으로 변환 가능
    - 금리 값의 범위 확인: 비정상(기준 확립 필요)적으로 큰 경우 경고 발생시키고 원본 확인

## 9. 증분 적재 전략	
- 적재 방식
  - 일별 적재에서는 YYYYmm 형식의 월별 XML을 사용
  - 초기/대용량 적재에는 연별 XML을 사용
  - 기존 CSV에 신규 데이터를 date 기준으로 추가
- 데이터 갱신 및 예외 처리
  - date를 고유키로 설정
  - 정기적으로 최근 데이터 수집해 기존 데이터와 비교하여 누락/변경 여부 확인
  - 검증을 통과한 후에만 갱신
- 적재 결과 저장
  - 결과를 CSV 형식으로 저장
  - CSV도 Github으로 관리
## 10. 실행 및 배포	
- GitHub Actions 실행 주기
  - 매일 정해진 시간에 Actions 실행
  - 수집, 정제, 검증, 갱신, 생성을 Actions에서 실행하여 서로 연결
  - 데이터 증분 적재 작업 흐름은 순차 실행
  - 기존 데이터 검증 작업은 병렬 실행
- 실패 처리
  - All or Nothing(실패하면 CSV에 덮어쓰지 않음)
  - 오류 메시지는 Github Actions에서 기록
  - 실패하면 시각화 생성 및 배포 진행하지 않음
- GitHub Pages 배포
  - CSV에 변경 사항이 있는 경우에만 배포 진행
  - 파이프라인이 성공했을 때만 배포 진행
