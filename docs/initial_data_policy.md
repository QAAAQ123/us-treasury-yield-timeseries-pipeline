## 1. 정상 결측
### 1.1. 주말 및 휴장일
#### 조건
- 날짜 목록에서 관측일 사이에 달력상 빠진 날짜가 있다.
#### 판정
- 빠진 날짜가 `주말` 또는 `휴장일`인지 판단할 수 있으면 해당 날짜를 정상 결측으로 판단한다.
- 빠진 날짜가 영업일이면 오류로 봐야 하지만, 영업일인지 아닌지를 판단할 수 있는 데이터나 API를 도입하지 않았기 때문에 영업일 오류를 판단하지 못한다.
- 따라서, 관측일 사이에 빠진 모든 달력 날짜를 정상 결측으로 판단한다.
#### 처리
- 빠진 날짜마다 직전 관측 레코드의 만기별 금리 값을 복제한다.
- 만기별로 이전 날짜를 다시 탐색하지 않는다.
- 직전 관측 레코드의 만기 값이 None이면 None을 그대로 복제한다.
- 첫 관측일 이전의 날짜는 생성하지 않는다.
#### 결과 값
- 직전 관측 레코드가 있는 경우: 해당 레코드의 만기별 값 복제
- 복제할 만기 값이 None인 경우: None


### 1.2. 만기별 제공 기간 정책
#### 조건
- 날짜가 해당 만기의 최초 제공일 이전이거나, 재무부 사이트 주석에 명시된 미제공 기간에 포함된다.
- 해당 만기의 값이 None이 아닌 경우
#### 판정
- 위 두 조건을 만족하면 해당 만기의 제공 정책 위반으로 판단한다.
- 다른 만기 값의 존재 여부는 확인하지 않는다.
#### 처리
- 해당 만기만 None으로 처리한다.
#### 결과 값
- None


## 2. 비정상
### 2.1. 날짜 필드 누락 또는 변환 실패
#### 조건
- 날짜 필드가 없거나 date로 변환이 불가하다.
#### 판정
- 날짜 필드 부재, date 변환 예외 발생
#### 처리
- 날짜를 알 수 없으므로 해당 레코드 제거
#### 결과 값
- 레코드 제거

### 2.2. 날짜 중복
#### 조건
- 같은 날짜가 두 개 이상의 레코드로 존재한다.
#### 판정
- 현재 레코드의 날짜가 직전 레코드의 날짜보다 빠르거나 같으면 오류로 판단한다.
#### 처리
- ValueError를 발생시킨다.
- 중복 레코드 제거 및 값 비교는 수행하지 않는다.
#### 결과 값
- 예외 발생


### 2.3. 만기 수익률 float 변환 실패
#### 조건
- 날짜는 정상이다.
- 다른 만기 값은 변환 가능하다.
#### 판정
- 특정 만기 값을 float로 변환할 수 없다.
#### 처리
- 해당 만기 값을 None으로 둔다.
- 원본 문자열을 로그로 남긴다.
#### 결과 값
- None
