## 회고

### 1. 목표 달성 평가
#### 구현을 완료한 항목(`pipeline.md` §1, §2 기준)
1. XML 데이터 수집(아카이브·연도별·월별): `extract.py`
2. XML 파싱 및 필드 추출, 자료형 변환: `transform.py`
3. 결측 처리(휴장일 직전값 복제, 만기별 제공 기간 정책): `missing_data.py`
4. Wide Format DataFrame 변환 및 Curve·Spread CSV 저장: `transform.py`, `load_csv.py`
5. 증분 적재(기존 CSV와 병합, 중복 제거, 변경 감지, 재검증): `load_csv.update_csv`
6. Plotly 시각화 HTML 생성: `visualize.py`
7. GitHub Actions 수집·배포 및 GitHub Pages 배포: `collect.yaml`, `deploy.yaml`
8. 테스트 및 CI: 단위·통합·E2E 테스트, `ci.yaml`, `e2e.yaml`

#### 구현하지 못한 항목과 미완성 사유
1. 계획 단계에서 의도적으로 보류
    - 휴장일과 실제 결측의 구분: 영업일 판단 데이터·API 미도입(`initial_data_policy.md` §1.1)
    - 금리 값 범위 검증: 비정상 값 판단 기준 미확립(`pipeline.md` §8)
2. 정책은 작성했으나 구현에서 단순화하거나 누락
    - 날짜·금리 변환 실패 처리: 레코드 제거·None 처리 대신 파이프라인 중단으로 구현
    - 날짜 필드 누락 처리: 처리 코드 없음
    - HTTP 재시도: 미구현
    - 최근 N개월 재수집을 통한 정합성 확인: 미구현
    - 통합·기간별 아카이브 일치 검증: 미구현
    - 증분 적재 시 월 경계 휴장일 미보정: 정책 §1.1 미충족
    - 월말 데이터 누락 가능: 최근 N개월 재수집 미구현과 연결
3. 계획에 없었고 리뷰에서 발견
    - HTTP 상태 코드별 처리

### 2. 잘한 점
- 조사 → 문서 → 구현 순서: notebook으로 XML 구조와 결측 패턴을 확인한 뒤 설계 문서를 쓰고, 모듈마다 문서를 먼저 작성한 후 구현했다.
- CSV만 저장하고 HTML은 배포 시점에 생성: 처음엔 Figure를 HTML로 저장하려 했으나, CSV를 단일 원천으로 두고 deploy에서 HTML을 만들어 배포했다. 저장소에 생성물이 쌓이지 않는다.
- 수집과 배포 workflow 분리: collect(수집·커밋)와 deploy(HTML 생성·Pages 배포)의 책임을 나눠 각각 독립적으로 실행할 수 있다.
- 공통 로거 설정 모듈: `logger_config.py` 하나로 모든 모듈의 로그 형식을 통일해, 모듈마다 로거를 설정할 필요가 없었다.
- 세부 동작을 정한 뒤 테스트 작성: 단위·통합·E2E 테스트로 검증해 실제 실행 디버깅 없이 정상 동작했다(단순한 프로젝트라 효과를 더 체감).

### 3. 아쉬운 점
- 설계: 연월 조회와 아카이브 조회의 URL 형식이 다르다는 점을 초기에 고려하지 못했다.
- 구현: 여러 모듈이 쓰는 상수를 공통화하지 않았다(`RECORD_KEY_MAP`은 `tr/ansform.py`·`missing_data.py`, dtype은 `load_csv.py`·`transform.py`·`pipeline.py`에 각각 정의).
- 테스트: 자주 쓰는 fixture·헬퍼를 `conftest.py`에 모으지 않았다.
- 문서-구현 동기화: 구현 중 바뀐 정책(변환 실패 시 중단 등)을 바로 반영하지 않아, 마지막에 문서에 `현재 구현` 주석을 몰아서 추가했다.
- 문서 작성 기준: 기준 없이 필요하다고 느낄 때만 문서를 작성해, 모듈마다 문서가 있기도 하고 없기도 했다.

### 4. 주요 문제 해결 경험
#### 결측 처리 정책 설계·구현
- 문제: 주말·휴장일, 만기별 미제공 기간(20Y·30Y 공백, 1.5M·2M·4M 신설), 실제 결측이 모두 "값 없음"으로 나타난다.
- 해결: 재무부 주석을 근거로 만기별 제공 기간을 상수화해 None 처리하고, 관측일 사이 빠진 날짜는 직전 관측값으로 채웠다. 영업일을 판단할 데이터가 없어 휴장일과 실제 결측은 구분하지 않기로 했다. 구현·테스트 후 정책 문서를 다시 수정했다(2026-10-31).
- 배운 점: 정책은 "판단할 수 없는 것"을 명시해야 구현과 테스트 범위가 정해진다. 또 정책은 구현 후 다시 확인해야 한다. 리뷰에서 변환 실패 처리가 정책과 달라진 것을 뒤늦게 발견했다.

#### 배포 전략
- 문제: HTML을 저장하지 않으면 배포할 때마다 CSV에서 다시 생성해야 하고, collect가 CSV를 커밋해도 deploy가 자동으로 실행되지 않는다.
- 해결: deploy에서 CSV를 읽어 HTML을 생성·검증한 후 배포하고, collect는 CSV가 바뀐 경우에만 `gh workflow run`으로 deploy를 직접 실행한다.
- 배운 점: workflow를 나눌 때는 실행 연결 방식(트리거 조건, 권한)까지 설계해야 한다.

### 5. 개선 방향
- 월 경계 휴장일 미보정: 증분 적재 시 기존 CSV의 마지막 레코드를 `handle_missing_data`의 시작 관측값으로 함께 넘겨, CSV 마지막 날짜와 이번 달 첫 관측일 사이를 채운다.
- 월말 데이터 누락: 증분 적재 시 현재 월과 직전 월을 함께 조회하거나, 최근 N개월 재수집 후 비교한다.
- 운영 안정성
    - HTTP 재시도와 상태 코드별 처리(4xx는 즉시 실패, 5xx·네트워크 오류는 재시도)
    - 날짜 필드 누락을 명시적으로 검증(`KeyError` 대신 의도한 예외)
    - 금리 값 범위 검증 기준 확립
